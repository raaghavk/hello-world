## Development Guidelines

### General Practices

- Keep code simple and well-documented
- Follow standard coding conventions for whatever language is added
- Write clear commit messages that describe the changes made
- Test any new features before committing

### Project Structure

Currently a minimal repository with:
- README.md: Basic introduction and project information

As the project grows, maintain clear organization:
- Source code in appropriate directories (e.g., `src/`, `lib/`)
- Documentation in the root or `docs/` directory
- Tests in a `tests/` or `__tests__/` directory
- Configuration files in the root directory

### Coding Standards

When code is added to this repository:
- Use consistent indentation (2 or 4 spaces, no tabs)
- Include comments for complex logic
- Write self-documenting code with clear variable and function names
- Add error handling where appropriate

### Git Workflow

- Work on feature branches (e.g., `feature/new-functionality`)
- Use descriptive branch names
- Keep commits atomic and focused on a single change
- Write commit messages in imperative mood (e.g., "Add feature" not "Added feature")

### Testing

When applicable:
- Write tests for new functionality
- Ensure all tests pass before pushing
- Aim for good test coverage of critical paths

### Documentation

- Keep README.md up to date with project changes
- Document any setup or installation steps
- Include usage examples for key features
- Update this CLAUDE.MD file as the project evolves
